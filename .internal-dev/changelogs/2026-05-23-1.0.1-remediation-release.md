# 2026-05-23 SimplyPages 1.0.1 Remediation Release

## Summary

- Merged the remediation PR stack into `codex/remediation-release-1.0.1`.
- Bumped parent, framework, demo, demo dependency, README, and getting-started install versions from `1.0.0` to `1.0.1`.
- Added a public migration guide for `1.0.1` contract-hardening targets and validation strategy.

## Compatibility Notes

Most existing code using valid component inputs should continue to work. The release intentionally
tightens several contracts, so code relying on permissive invalid input can fail fast:

- Invalid tag names, attribute names, unsafe inline style values, and unsafe public URLs now throw
  `IllegalArgumentException` in hardened render/build paths.
- Module width helpers remain blocked; callers should size modules with `Row`/`Column` layout
  containers.
- Row/grid/layout token helpers reject unsupported tokens instead of emitting drifted CSS classes.
- `ValidationResult.getErrors()` returns an immutable defensive copy.
- Editable page, row, module, and modal IDs used in generated editing paths must be safe path
  segments.
- Editing demo endpoints enforce server-side permissions and bounds instead of trusting hidden UI
  controls.
